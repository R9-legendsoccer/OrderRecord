# 🍽️ 学校订餐记录系统 - 程序使用、迁移与运维说明文档

本系统基于 **Python + Streamlit + OCR 智能识别引擎** 开发，专为学校食堂长截图账单设计。旨在实现“AI 智能初筛提取 + 人工快速复核”的高效账目管理，保障历史数据零丢失、退餐精准剔除及独立页面按周打印。

---

## 一、 系统核心功能特性

1. **智能时间推算**：依据设定的“本学期第一周周一”基准日期，自动将截图中的日期归算为规范的“学期”与“周次”。
2. **退餐智能剔除**：自动识别并标记“退餐/未取餐”状态，确保在总消费统计中自动扣除无效账目。
3. **行号安全保护 (`_row_id`)**：底层采用唯一行号机制，无论进行全表修改、新增还是单行删除，均能确保其余历史周次数据绝对不丢失。
4. **独立页面按周打印**：支持一键生成纯净的专属打印页面，完美避开浏览器沙盒拦截，自由选择学期与周次进行纸质或 PDF 打印。

---

## 二、 📷 支持的图片样式与排版规范

为了让 OCR 引擎能够以最高准确率识别截图，请尽量遵循以下图片样式规范：

* **图片格式**：支持常见的高清图片格式（`.png`、`.jpg`、`.jpeg`）。
* **内容构图**：
* 建议上传**整周订餐长截图**（包含早、中、晚餐的完整排版）。
* 截图应包含清晰的**日期、餐别（早/午/晚餐）、食堂名称（第一/第二食堂）、套餐代号（如 A/B/C/D/E/G/L/M/N 等）、菜品明细及价格**。


* **清晰度要求**：图片应保持适当的清晰度，避免过度模糊、严重压缩或强烈的曝光反光，确保英文字母（如 `B`、`D`、`G`、`L`）和括号内的数量词清晰可辨。

---

## 三、 ⚠️ OCR 识别高频易错点说明

由于机器视觉的局限性，在处理密集的食堂菜单时，可能会出现以下几类高频识别错误。系统已内置多重正则规则进行自动补齐，但对于极少数极端情况仍需人工复核：

### 1. 英文字母吞字或误认

* **现象**：部分套餐代号（如 `B套餐`、`D套餐`、`G套餐`、`L套餐`）由于字体或像素问题，字母可能被漏掉，或者 `L套餐` 容易被误认成“`匕套餐`”。
* **应对机制**：系统内置了形近字过滤与特定菜品关联兜底（如带有“菠萝咕咾肉”会自动校正为 E 套餐，“锅包肉”校正为 L 套餐）。若仍有漏网之鱼，直接在右侧表格修改即可。

### 2. 数量词“数字失踪”

* **现象**：括号内的数量词（如 `(2张)`、`20个`、`2根`、`1份`）的数字有时会被漏掉，只剩下光秃秃的 `(张)`、`个` 或 `份`。
* **应对机制**：系统已针对高频词（如 `(张)` 自动补为 `(2张)`、`水煮蛋个` 自动补为 `水煮蛋1个`、`猪肉白菜馅20个` 等）设置了强制修复正则。

### 3. 生僻汉字形近误读

* **现象**：例如“**干**煸”的“干”字有时会被 OCR 误认为是“**千**”字（变成“千煸菜花”）。
* **应对机制**：系统已对常见词汇（干煸、干锅等）进行了自动规整与纠错。

### 4. 长图切片导致的行漏或重复

* **现象**：超长的截图在分段切片识别时，极少数边缘行可能出现漏识别，或者在重叠区域出现多识别一次的冗余现象。

## 四、 💡 推荐的高效工作流：“AI 初筛 + 快速复核”

鉴于 OCR 无法做到 100% 绝对无错，本系统推荐采用以下最稳妥、最高效的操作闭环：

1. **AI 智能提取**：上传截图，系统自动完成日期切分、菜品拼接、价格提取与退餐判定。
2. **右侧表格快速扫视**：在系统的 Streamlit 可视化表格中花 1 分钟快速浏览，顺手点改个别字母（如补上 `G`）或错别字。
3. **一键锁定保存**：点击 **`💾 保存当前表格修改（全表安全合并）`** 按钮，数据即刻永久写入 `meal_records.csv` 数据库中。

## 五、 🚀 新电脑迁移与多环境部署指南

### 1. 准备项目文件

在旧电脑上，将整个项目文件夹（包含 `orderrecord.py` 和 `meal_records.csv`）通过 U盘 或压缩包整体迁移到新电脑。

### 2. 安装 Python 与运行库（二选一）

打开新电脑终端（PowerShell），进入项目目录后，根据硬件及环境选择合适的安装命令：

* **场景一：常规默认部署（EasyOCR 引擎，推荐且稳妥）**
```powershell
py -3.12 -m pip install easyocr opencv-python streamlit pandas pillow torch torchvision -i https://pypi.tuna.tsinghua.edu.cn/simple

```


* **场景二：高性能部署（支持百度飞桨 PaddleOCR 引擎）**
```powershell
py -3.12 -m pip install paddlepaddle paddleocr opencv-python streamlit pandas pillow -i https://pypi.tuna.tsinghua.edu.cn/simple

```


*(注：若飞桨在特定 Windows/Python 3.12 环境下初始化失败，代码会自动降级切回 EasyOCR，确保系统稳定。)*

### 3. 启动程序

```powershell
py -3.12 -m streamlit run .\orderrecord.py

```

## 六、 🤖 附：利用 AI 工具批量转换历史截图技巧

如果你手头积累了大量历往周次的订餐长截图，且希望在导入系统前直接通过 AI（如 ChatGPT、Claude 或 Gemini）一次性批量转成符合本程序标准的 CSV 格式文件：

1. **将截图喂给 AI**：
将你需要整理的多张订餐长截图一次性发送给 AI 助手。
2. **使用标准提示词（Prompt）**：
向 AI 提供如下指令，让其直接输出标准格式：
> *“请帮我识别以下各周的订餐长截图，并严格按照本系统要求的 CSV 格式输出。表头必须包含：`学期,周次,日期,餐别,菜品种类,价格(元),状态,餐食评价`。请确保学期为‘X年级第X学期’，状态包含‘取餐’或‘退餐’，菜品种类未提及食堂为第一食堂，提及的都是第二食堂，菜品种类格式形如‘[第一食堂] B套餐: ...’。请直接输出可以保存为 `meal_records.csv` 的标准 CSV 文本。”*


3. **直接覆盖导入**：
将 AI 输出的 CSV 文本内容复制并保存覆盖到项目根目录下的 `meal_records.csv` 文件中，启动程序后即可直接在网页端完美呈现所有历史账目！
